# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## What this is

Aria is a "reverse tutor": the user teaches, and an AI student (powered by OpenAI Codex via the user's own ChatGPT account) responds with calibrated confusion and probing questions. The server spawns `codex app-server` as a child process — the Codex CLI (`npm install -g @openai/codex`) must be on PATH for anything beyond `/api/health` to work.

The app has since grown a **learning-coach front door** (`CoachShell`): the home screen is a chatbot-style shell where each "learning project" is a notebook, and an AI **coach** — grounded in a curated learning-science knowledge base (`kb/`, distilled from Justin Sung) — advises the user on HOW to learn (technique selection, study planning, a Socratic no-answers-without-an-attempt stance). Teach-back with the Aria student is now one technique the coach recommends and the user launches from the project header.

Use "Aria" in the product sense to mean both the system and the AI student the user is teaching. In implementation notes, be precise about the layer: the app/server orchestrates notebooks, sessions, sources, and Codex threads; the in-character Aria student is the Codex thread shaped by `persona.ts`; its learned state is the server-owned belief inventory; the learning **coach** is a third Codex persona (`coach.ts`) with its own per-notebook thread.

## Commands

```bash
npm install          # once, at the repo root (npm workspaces)
npm run dev          # backend (Express, :5275) + frontend (Vite, :5173) together
npm run dev:server   # backend only (tsx watch)
npm run dev:web      # frontend only; Vite proxies /api → localhost:5275
npm run typecheck    # tsc on both workspaces — the only check; there is no lint or test suite
npm run build -w @aria/web   # frontend production build (also runs web typecheck)
npm run start -w @aria/server # run the backend once without watch
```

Regenerate a Material 3 palette block for `web/src/theme/tokens.css`: `node web/scripts/gen-m3-palette.mjs "#42A5F5"`.

## Layout

npm workspaces monorepo: `server/` (`@aria/server`, Express 5 + TypeScript, ESM via tsx) and `web/` (`@aria/web`, React 19 + Vite). Runtime state lives in `data/` (gitignored content): `data/settings.json` plus one directory per notebook at `data/notebooks/<id>/` holding `notebook.json` (metadata + full chat transcript), `sources/` (uploaded files and discovered web sources), and optionally `rag-index.json` (server-only retrieval index). Local embedding models are cached under `data/models/`. The learning-coach knowledge base is a checked-in `kb/` corpus (curated principle/technique docs + cleaned transcripts) indexed once to `data/kb-index.json`.

The server is ESM with NodeNext resolution — relative imports must use `.js` suffixes (`import ... from "./config.js"`), even though sources are `.ts`.

## Server architecture

Composition root is `server/src/index.ts`; `app.ts` wires routes and a gate middleware that 503s every `/api` route except `/api/health` unless the app-server is `running`.

**`appserver/`** — `AppServerClient` (client.ts) owns the single long-lived `codex app-server` child: JSON-RPC over stdio (framing in rpc.ts, request/response types in protocol.ts), typed method wrappers (`thread/start`, `turn/start`, …), per-thread notification routing via `subscribeThread`, and crash supervision with backoff (gives up after repeated failures within 60s → state `dead`). Each respawn increments `client.generation`; sessions compare it to know when a Codex thread needs `thread/resume`. The student runs in a **read-only sandbox with `approvalPolicy: "never"`** — approval requests should never happen and are auto-declined so a misconfiguration can't hang a turn.

**`domain/`** — the core logic:
- `store.ts` — `NotebookStore`: in-memory map, persisted per notebook as JSON via atomic writes chained per-notebook so saves apply in order.
- `settings.ts` — global settings (`model`, `effort`, `replyLength`, `probing`, `ragMode`, `ragRecall`). `ARIA_MODEL`/`ARIA_EFFORT` env vars only *seed* the file on first boot; afterwards the file (Settings UI) wins.
- `persona.ts` — the student persona, developer instructions, kickoff prompt, and transcript catch-up block. The `"default"` reply-length/probing rule strings are the original prompt text verbatim, kept so default settings produce a byte-identical persona — don't reword them casually.
- `learning.ts` — Aria's **private student belief state**: a server-owned inventory (`learningState` on the notebook, statuses `unknown | misconception | partial | understood`) deciding WHAT the in-character student knows, kept strictly separate from the persona (HOW it speaks). Generated at kickoff by a one-shot side call (`AppServerClient.runOneShotTurn`, ephemeral thread), injected into every student turn as a hidden `[BELIEF STATE]` block, and updated only by a strict per-turn evaluator pass before the student replies — a vague explanation must not resolve a misconception (at most `challenged`). This state is not the visible knowledge map.
- `knowledge.ts` — the visible **user knowledge map**: a separate persisted `userKnowledgeState` inferred from teacher messages only. Topic/source material defines the concept graph (`area` clusters + `deps` edges), but every fresh node starts `unknown`; uploaded or discovered sources never credit knowledge by themselves. A teacher-message evaluator updates `unknown | partial | misconception | understood` before Aria replies, rewinds rebuild from the surviving teacher-message prefix, and source changes rebuild the graph while replaying teacher evidence. It ships as `knowledgeState` on `GET /api/notebooks/:id` and `knowledge-state` SSE events; `KnowledgeMapView` renders this state. `ARIA_NO_LEARNING_STATE=1` disables both private belief state and the visible map.
- `intake.ts` — pre-session setup ("tune Aria"): deterministic level/research questions plus up to two generated focus questions. Answers calibrate private learning-state generation, can request pre-kickoff online source discovery, and are answered once before kickoff. `ARIA_NO_INTAKE=1` disables the form for new notebooks.
- `discover.ts` — online source discovery. A web-search-enabled Codex turn finds public URLs, then the server downloads/extracts them into individual source files (`origin: "research"`, optional `originUrl`) that are previewable, deletable, and RAG-indexed. It powers intake research and the mid-session "Find online" action, fails open per URL, and uses `ARIA_RESEARCH_EFFORT` (default `medium`) plus `ARIA_DISCOVER_MAX` (default `5`, clamped 1–10).
- `rag.ts` — server-side retrieval over source files. Large readings (or any reading when `ragMode: "always"`) are chunked and embedded with Transformers.js, saved to `rag-index.json`, and recalled as hidden excerpts before non-kickoff turns. It fails open and can be disabled with `ARIA_NO_RAG=1`; other knobs are `ARIA_RAG_MODEL`, `ARIA_RAG_MIN_WORDS`, and `ARIA_RAG_WAIT_MS`.
- `session.ts` — `SessionManager`, the heart of the app. One `NotebookSession` per notebook: turn state machine (`idle → starting → streaming`), SSE fan-out to attached browsers, a 5-minute inactivity watchdog that interrupts and then force-resets a wedged turn, and overload retry on `turn/start`.
- `cyra-session.ts` / `cyra.ts` — "Ask Cyra" expert-teacher threads. These are separate Codex threads stored under `notebook.cyraThreads`, run concurrently with the Aria student thread, use source retrieval with expert framing, and intentionally mirror only the generic session mechanics instead of sharing the dense Aria kickoff/evaluator code.
- `coach-session.ts` / `coach.ts` — the **learning coach**: one thread per notebook (`notebook.coach`), a lean mirror of the Cyra session pair. Its pinned persona bakes in a condensed core learning model (kept in sync with `kb/core-model.md`) plus a technique menu and a Socratic gate (no answers without a visible attempt); each turn injects two hidden fail-open blocks — knowledge-base passages (`kb.ts`) and the learner's own source excerpts (`rag.ts`). Its kickoff is a **visible** streamed greeting (no belief machinery) that skips whatever the creation-time calibration answers (`notebook.coachIntake`: goal/current/deadline, also pinned into instructions) already covered. The persona may emit at most one fenced ```quiz block (JSON) per reply, rendered client-side as an interactive check-for-understanding card — or one ```choices block (clickable decision buttons with optional app actions `upload-sources`/`find-sources`); a no-sources kickoff must end with the sources choices block. It also drafts learning-log entries as ```log blocks and runs the session-open ritual driven by `journey.ts`'s hidden `[SESSION]` block. Sources added after the pinned manifest (uploads/discovery/links) queue on `coach.pendingSourceNotes` and surface as a hidden preamble on the next turn. Knobs: `ARIA_COACH_EFFORT`.
- `links.ts` — creation-time link ingestion: URLs pasted in the create dialog download in the background into sources (non-YouTube via `downloadDiscoveredSources`; YouTube via `yt-dlp` transcript extraction, fail-open when the binary is missing, canonical watch-URL dedupe). Registers in-flight jobs so `POST /:id/coach/kickoff` can `awaitLinkIngestion` (45s cap, post-wait idempotency re-check, `sourcesPending` greeting fallback). Deliberately does NOT stamp `pendingNewSources` (no Aria thread exists yet).
- `usage.ts` — **`UsageStore`** (`data/usage.json`, the `SettingsStore` global pattern): app-wide technique-usage counts and the adaptive **coaching mode** (`guided | intermediate | experienced`). Counts are written only by server-side instrumentation in `routes/notebooks.ts` (guided-reading creation by level, teach-back sessions gated on a 4h gap, Cyra "ask-expert" creation), never by the client. `renderProfileBlock()` injects a hidden `[USER PROFILE]` block into every non-kickoff coach turn so the coach fades scaffolding after ~5 uses (kb: scaffolds-to-independence); the mode rewrites the coach persona (`MODE_RULES` in `coach.ts`) and a mode change rebuilds the coach thread via the `coach.appliedMode` drift check (mirrors `appliedStyle`). Routes: `GET/PUT /api/usage` (only `coachMode` is writable).
- `reading.ts` — **guided reading**: a one-shot KB-grounded pass over a PDF source's per-page text (`extract.ts`'s `extractPdfPageTexts`, page-batched) that emits text-quote-anchored annotations (`pause | simplify | compare | connect | judge | apply | technique`) plus after-reading suggestions, stored as `notebook.readingSessions`. Anchors that don't verify against the extracted page text are dropped server-side; generation is async (`status: "generating" → "ready"/"failed"`, orphan recovery on GET), page batches run **concurrently** with annotations persisted incrementally as each batch lands (the view polls), and pages are also rendered to PNGs (`pdf-images.ts`: pdfjs-dist legacy + `@napi-rs/canvas`, fail-open) and attached as `localImage` turn inputs so the pass can SEE figures/diagrams/slides — with a text-only retry if image inputs are rejected. Prompt density fades with the session's level (beginner/intermediate/experienced — see `kb/principles/scaffolds-to-independence.md`). Routes: `POST/GET /:id/reading`, `GET /:id/reading/:rid`, `PATCH .../annotations/:aid`, `DELETE /:id/reading/:rid`. Knob: `ARIA_READING_EFFORT` (default `medium`).
- `journey.ts` — the **study-journey layer**: sessions, the learning log, and loose spaced returns (all pure functions). Sessions are DERIVED from coach-message timestamps (`SESSION_GAP_MS` = 4h, shared with the teach-back new-session counter); `splitSessions` segments the transcript. The learning log (`notebook.learningLog`, `LearningLogEntry` in store.ts) is the durable session record — one entry per study block (topic/goal/strategy/resultGap/nextMove), coach-drafted via a ```log block or added manually; entry id `log:<coachMessageId>` makes confirms idempotent. `computeDueTopics` groups entries by normalized topic and marks a topic due on expanding gaps (`RETURN_INTERVALS_DAYS` = [1,3,7,14,30], clamped), capped at 3, retiring topics untouched >60 days — computed on read, never stored (no rigid "Anki hell" scheduling). `buildSessionBlock` injects a hidden `[SESSION]` ritual preamble on the first coach turn after a >4h silence (retrieval-of-last-time first, then a one-line target as a ```choices block, or a backfill ```log card when the previous block went unlogged). Routes: `GET/POST /:id/log`, `PATCH/DELETE /:id/log/:eid` (in notebooks.ts) plus `GET /api/journey/due` (cross-project, `routes/journey.ts`). Web: `views/coach/JourneyDialog.tsx` (the Journey chip panel), `LogEntryCard.tsx` (the ```log confirm card), the SessionBar in `CoachChatView.tsx` (goal pill / wrap-up / welcome-back), and the sidebar "worth a quick return" strip, all sharing `journeyContext.ts`; canonical message strings live in `lib/journeyMessages.ts`.
- `kb.ts` — the global learning-coach knowledge base index. Reuses `rag.ts`'s chunker/embedder/scoring internals over the static `kb/` corpus, builds/refreshes `data/kb-index.json` on boot (fingerprint check) and lazily per turn, and retrieves coaching passages with no per-source filtering. Fails open; kill switch `ARIA_NO_KB=1` degrades the coach to persona-only.

Key invariants in the session layer:
- **One Codex thread per notebook** (the student remembers what it was taught). `developerInstructions` are pinned at thread creation and NOT re-applied on resume — so changing student style starts a *fresh* thread and prepends a transcript catch-up block (`catchUpNeeded`) to the next turn. The applied style is recorded on the notebook (`appliedStyle`) to detect drift.
- **The kickoff turn** (first turn of a notebook, `kickoffDone` flag) is hidden from the UI: deltas aren't broadcast, completed messages are buffered, and only the final agent message is rendered/persisted as the student's opener. Kickoff runs at `max(medium, chosen effort)` unless `ARIA_KICKOFF_EFFORT` pins it.
- **The intake pipeline gates kickoff** for new notebooks when enabled: clients must submit `POST /api/notebooks/:id/intake` before any Aria turn can start. If research is requested, `SessionManager.runIntakePipeline` discovers and downloads online sources first, then starts the hidden kickoff. Notebooks created from the coach shell (`createdVia: "coach"`) **defer** intake init until the teach-back view is first opened (`GET /:id`), so a project that never launches teach-back never generates intake questions.
- **Rewind editing is destructive by design**: `POST /api/notebooks/:id/messages/:mid/edit` replaces a past teacher message, deletes that message and everything after it, abandons the Codex thread, re-derives the belief inventory from the surviving prefix, then sends the edited text as a fresh turn. Cyra mirrors this at `/cyra/:tid/messages/:mid/edit`.
- **Source changes after kickoff are queued into the next turn**: uploads accept `.txt`, `.md`, and `.pdf` only, max 10 files / 25MB each; PDFs get a sibling `.extracted.txt` when text extraction succeeds. Because thread instructions are pinned, added/removed files are recorded as `pendingNewSources` / `pendingRemovedSources` and injected as hidden notes on the next student turn; explicit upload/delete also retries and rebuilds the RAG index.
- Teacher messages are persisted optimistically before `turn/start` and rolled back if it fails; partial student text is persisted with `interrupted: true` when a turn is interrupted/failed.
- Thread notifications are filtered by `turnId` to guard against late/duplicate events.

SSE protocol (one channel per notebook, `routes/notebooks.ts` → `lib/sse.ts`): events `state` (snapshot on attach), `turn-started`, `delta`, `message`, `activity` (`reading-sources` | `thinking` | `researching`), `knowledge-state`, `sources-updated`, `discover-completed`, `notice`, `error`, `turn-completed`, each with an incrementing per-session `id`. Cyra threads have their own `/cyra/:tid/events` channel with the same streaming events minus kickoff/intake/source-discovery fields; the coach has one `/coach/events` channel per notebook (its `state` event carries `kickoffDone`).

## Web architecture

Routing/auth shell in `App.tsx`: an auth gate (`lib/auth.tsx`) with phases `checking | backend-down | signed-out | waiting-oauth | signed-in` wraps three routes: `/` and `/learn/:id` (`CoachShell` — the coach front door: sidebar of learning projects + the project's coach conversation) and `/notebook/:id` (`SessionView` — teach-back with the Aria student).

- `lib/useTeachingSession.ts` is the streaming chat hook: subscribes to the notebook's SSE channel, buffers deltas and flushes them on `requestAnimationFrame`, reconciles streaming items (id prefix `streaming:`) with persisted messages, and drives the intake/research/kickoff loading states.
- `lib/useCoachThread.ts` + `views/coach/CoachChatView.tsx` are the coach equivalents (mirroring the Cyra hook/view), with a once-guarded auto-kickoff so a fresh coach greets the user. `CoachShell` foregrounds this; teach-back stays in `SessionView`. Coach markdown is post-processed (`lib/techniques.ts`): known technique names become chips with a viewport-aware floating why/when tooltip (position:fixed, flips/clamps, closes on scroll), ```quiz fenced JSON renders as a clickable quiz card, and ```choices fenced JSON renders as decision buttons (live only on the last coach message while idle; actions arrive via `coach/coachActions.ts` contexts — `CoachShell` provides open-add-sources / find-sources, and subscribes to the notebook's `/:id/events` SSE channel so sources/discovery updates refresh live). The create dialog is three fields: topic, familiarity, optional materials (files + pasted links).
- Settings → **Coaching style** (`SettingsDialog`) drives the global coaching mode via `PUT /api/usage`; the `ReadingDialog` reads `GET /api/usage` to default the level one step lighter after ~5 uses (with a visible nudge). Both implement scaffold fading.
- `views/reading/ReadingView.tsx` (route `/learn/:id/read/:rid`) is the guided-reading pane: pdf.js (`pdfjs-dist`) pages rendered lazily (IntersectionObserver) as canvas + text layer, annotation anchors located in the text layer by whitespace-tolerant quote matching and marked as kind-tinted highlight spans, with a prompt rail (respond/resolve per annotation, "Discuss with coach" posts the passage + prompt + answer into the coach conversation). `views/reading/ReadingDialog.tsx` is the entry point from the shell header.
- `lib/useCyraThread.ts` is the parallel streaming hook for "Ask Cyra"; `SessionView` switches between the main Aria thread and Cyra expert threads via `ThreadBar`. A split-chat preference (settings dialog "Chat layout", localStorage via `lib/splitChat.ts`) instead pins one Cyra conversation beside the Aria pane on wide windows (≥1141px): the Cyra chips move to the right pane's own bar, "Ask Cyra" merges the question into that pane's composer rather than opening a new thread (a thread is created only when none exists), and the knowledge map always takes the full panel (the Cyra pane steps aside while the map is open).
- `components/` is a hand-rolled Material 3 (Expressive) component library — each component is a `.tsx` + `.css` pair styled exclusively with `--md-sys-*` CSS variables from `theme/tokens.css`. No component framework; match this pattern for new UI.
- Theming is attribute-driven on `:root`: `data-palette` (`blue` default | `purple`) × `data-theme` (`dark` | light default), four token blocks at equal specificity. Blue is generated by `gen-m3-palette.mjs`; purple is material-web baseline kept verbatim.

## Project status & handoff (July 2026)

**Vision:** an education app that tells you HOW to learn anything, grounded in Justin Sung's learning science. The coach prescribes techniques matched to task + stage, makes the user work (Socratic gate), and fades its scaffolding as habits internalize (`kb/principles/scaffolds-to-independence.md` is the design law). All three originally planned phases are built: coach front door (V1), guided PDF reading (Phase 2), usage tracking + adaptive modes (Phase 3), plus a cold-start round (link/YouTube ingestion, ```choices buttons, 3-field creation, why/when tooltips).

**Branch state:** everything lives on `learning-coach`, pushed to `origin` (https://github.com/78i87/ariaask — **PUBLIC repo**). Not merged to `main`. The repo history was rewritten before first push to strip `kb/transcripts/` — verbatim Justin Sung video transcripts are **copyrighted, gitignored, local-only**; NEVER commit them. The distilled `kb/` docs are original writing and carry all coachable content (the coach works fully without transcripts). Local transcripts (10 files) add retrieval depth on this machine only; regenerate elsewhere via `scripts/kb-fetch-transcript.mjs` + `kb-clean-transcript.mjs` (needs `yt-dlp` on PATH — optional dep, everything fails open without it).
